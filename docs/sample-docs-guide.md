# サンプル文書の作り方（36 件 = 6 部署 × 6 件）

取り込みパイプラインが正しく読めるように、次の形式で作ってください。
既存の 4 件（`case7-doc1〜4`）と同じ書き方で問題ありません。

## 1. ファイルの置き場所

```
data/docs/
├─ strategy/    戦略
├─ operations/  業務
├─ it/          IT
├─ hr/          人事
├─ sales/       営業
└─ admin/       管理
```
- フォルダ名が部署の判定に使われます（本文の冒頭行があればそちらが優先）
- 各部署 6 件の内訳の目安: PDF 4 件 + Word（.docx）2 件
- ファイル名は英数字とハイフンのみ推奨（例 `strategy-05-retail-mid-term-plan.pdf`）

## 2. 文書のテンプレート（Markdown で書く）

```markdown
# ○○向け ○○提案書（サマリ版）

**部署: 戦略 / 客先: 地方銀行A / 作成: 2024年 / 機密度: 社外秘**

> 案件7 の取り込み用サンプル文書です。実在の企業・案件とは関係ありません。

## 1. 案件概要
（2〜4 文）

## 2. 現状の課題
- 箇条書き 3 つ程度

## 3. アプローチ
- 箇条書き 3 つ程度

## 4. 効果・ROI 試算
- **数値を必ず 2〜3 個入れる**（例: 月480万円→310万円、35%削減、回収 2.5 年）

## 5. スケジュール・体制
- 1〜2 行
```

守ってほしい点
- **2 行目の `部署: ○○ / 客先: ○○ / 作成: ○○年`** は必須。部署名は 戦略 / 業務 / IT / 人事 / 営業 / 管理 のいずれか
- 見出しは `## 1. 〜` の番号付き。チャンク分割がこの見出しで切れます
- 各文書に固有の数値・固有名詞（客先名・製品名）を入れると、テスト質問の「正解」が作りやすくなります
- 1 件あたり 400〜800 字で十分です（既存 4 件と同程度）

## 3. Markdown → Word / PDF

- Word: `模擬案件7\.claude\worktrees\mvp-scaffold` フォルダで
  ```
  npx tsx scripts/md-to-docx.ts <mdファイル or フォルダ>
  ```
  見出し・箇条書き・太字が Word のスタイルに変換されます
- PDF: Markdown を Word で開いて「エクスポート → PDF」、または VS Code の Markdown PDF 拡張、または Google ドキュメント経由で保存

## 4. 部署別テーマ案（迷ったときの参考）

| 部署 | テーマ例（客先の業種を変えて 6 件） |
|---|---|
| 戦略 | 中期経営計画策定、新規事業参入評価、M&A デューデリ、DX ロードマップ、海外展開戦略、価格戦略見直し |
| 業務 | 受発注業務の BPR、コールセンター効率化、在庫管理改善、RPA 導入、購買プロセス標準化、品質管理体制 |
| IT | クラウド移行、基幹システム刷新、セキュリティ評価、データ基盤構築、SaaS 選定、IT 内製化支援 |
| 人事 | エンゲージメント調査、人事制度改定、採用ブランディング、研修体系設計、タレントマネジメント、働き方改革 |
| 営業 | 会員アプリ活性化、営業プロセス改革、CRM 導入、代理店チャネル戦略、価格交渉力強化、EC 売上拡大 |
| 管理 | 経費精算の電子化、内部統制強化、予算策定プロセス改善、契約管理システム導入、監査対応、BCP 策定 |

Q13（業務）・Q14（管理）のテスト質問は、この中から作った文書に合わせて一緒に決めます。

## 5. 「該当なし」テストのために入れてはいけない内容
- 医療業界（Q10）、新型コロナ対策（Q11）、宇宙開発（Q15）に関する文書は作らないでください。これらは「存在しないテーマ」として使います。
